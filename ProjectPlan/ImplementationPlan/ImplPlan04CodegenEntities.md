**Duration:** 4 days · **Owners:** Vaibhav Gupta (token design), Vaibhav Gupta (emission)
**Exit gate G3:** the generated crate compiles with zero warnings under

---

## Output shape

`ruprizzle generate` writes into `generator.output` (default `src/db/`):

```
src/db/
├── mod.rs           # re-exports, the `Db` client root, prelude
├── enums.rs         # generated Rust enums + sqlx Type impls
├── user.rs          # struct User, mod user (tokens), UserInsert, UserUpdate
├── post.rs
└── _generated.rs    # DO NOT EDIT banner, schema hash, ruprizzle version
```

One module per model, not one giant file. Rust compiles modules in parallel and
IDEs stay responsive; a 60-model schema in a single file is a bad experience.

Every file starts with:

```rust
// @generated by ruprizzle 0.1.0-alpha.1 — DO NOT EDIT.
// Source: schema.ruprizzle (sha256:3f9a…)
// Regenerate with: ruprizzle generate
#![allow(clippy::all, unused_imports)]
```

The schema hash lets the CLI detect stale generated code and refuse to run
migrations against it.

## P3-01 · Entity structs

**Owner:** Vaibhav Gupta · **Est:** 5h

```rust
// src/db/user.rs

/// A registered account.
#[derive(Debug, Clone, PartialEq, sqlx::FromRow, serde::Serialize, serde::Deserialize)]
pub struct User {
    pub id:         uuid::Uuid,
    pub email:      String,
    pub name:       Option<String>,
    pub role:       crate::db::enums::Role,
    #[sqlx(rename = "created_at")]
    pub created_at: chrono::DateTime<chrono::Utc>,
    #[sqlx(rename = "updated_at")]
    pub updated_at: chrono::DateTime<chrono::Utc>,

    /// Loaded only when requested via `.include(user::posts())`.
    #[sqlx(skip)]
    #[serde(skip_serializing_if = "Related::is_absent", default)]
    pub posts: Related<Vec<super::post::Post>>,
}
```

**`Related<T>` instead of `Option<T>`** for relation fields. This is a deliberate
correctness choice:

```rust
// crates/runtime/src/related.rs
#[derive(Debug, Clone, PartialEq)]
pub enum Related<T> {
    /// Not requested in this query. Reading it is a programmer error.
    Absent,
    Loaded(T),
}

impl<T> Related<T> {
    /// Panics with an actionable message if the relation was not included.
    pub fn get(&self) -> &T { /* panic!("relation `posts` was not loaded — add \
                                  `.include(user::posts())` to your query") */ }
    pub fn try_get(&self) -> Option<&T>;
    pub fn is_absent(&self) -> bool;
}
```

`Option<Vec<Post>>` would conflate "not loaded" with "loaded, and empty" — the
classic ORM footgun where an empty list silently means "you forgot the include."
`Related` makes the two states distinguishable and the failure loud and
self-explaining.

Also emitted per model: `UserInsert` (required fields required, defaulted fields
`Option`) and `UserUpdate` (all fields `Option`, plus explicit-null support). See
ImplPlan05.

## P3-02 · Column tokens — the type-safety core

**Owner:** Vaibhav Gupta · **Est:** 8h

This is what buys us Drizzle-grade compile-time safety without Diesel's notorious
type-level machinery and error messages.

```rust
// src/db/user.rs  (continued)
pub mod user {
    use ruprizzle::col::Column;
    use super::User;

    pub const TABLE: &str = "users";

    pub const ID:         Column<User, uuid::Uuid>            = Column::new("users", "id");
    pub const EMAIL:      Column<User, String>                = Column::new("users", "email");
    pub const NAME:       Column<User, Option<String>>        = Column::new("users", "name");
    pub const ROLE:       Column<User, crate::db::enums::Role> = Column::new("users", "role");
    pub const CREATED_AT: Column<User, DateTime<Utc>>         = Column::new("users", "created_at");
}
```

And in the runtime:

```rust
// crates/runtime/src/col.rs
pub struct Column<M, T> {
    pub table:  &'static str,
    pub column: &'static str,
    _marker: PhantomData<fn() -> (M, T)>,
}

impl<M, T> Column<M, T> where T: Encodable {
    pub fn eq(self, v: impl Into<T>)  -> Filter<M>;
    pub fn ne(self, v: impl Into<T>)  -> Filter<M>;
    pub fn in_(self, v: Vec<T>)       -> Filter<M>;
    pub fn asc(self)  -> OrderBy<M>;
    pub fn desc(self) -> OrderBy<M>;
}

// Comparison operators only exist for ordered types.
impl<M, T: Ord + Encodable> Column<M, T> {
    pub fn gt(self, v: T) -> Filter<M>;
    pub fn gte(self, v: T) -> Filter<M>;
    pub fn lt(self, v: T) -> Filter<M>;
    pub fn lte(self, v: T) -> Filter<M>;
    pub fn between(self, lo: T, hi: T) -> Filter<M>;
}

// String operators only exist for strings.
impl<M> Column<M, String> {
    pub fn contains(self, v: &str)    -> Filter<M>;
    pub fn starts_with(self, v: &str) -> Filter<M>;
    pub fn ends_with(self, v: &str)   -> Filter<M>;
    pub fn ilike(self, pat: &str)     -> Filter<M>;
}

// Null checks only exist for optional columns.
impl<M, T> Column<M, Option<T>> {
    pub fn is_null(self)     -> Filter<M>;
    pub fn is_not_null(self) -> Filter<M>;
}
```

**What this buys, enforced by the compiler:**

| Mistake | Result |
|---|---|
| `user::EMAIL.eq(42)` | type error: `i32` is not `String` |
| `user::EMAIL.gt("a")` | no method — `String` is `Ord` but we gate `gt` to non-string ordered types |
| `user::ID.contains("x")` | no method — `contains` only on `Column<M, String>` |
| `user::EMAIL.is_null()` | no method — column is not `Option` |
| `db.select::<Post>().filter(user::EMAIL.eq(..))` | type error: `Filter<User>` ≠ `Filter<Post>` |

That last row is the important one. The `M` phantom parameter prevents mixing
columns from different models into one query — a whole class of runtime SQL errors
becomes a compile error, with a readable message (`expected Filter<Post>, found
Filter<User>`) rather than Diesel's page-long trait resolution dumps.

`PhantomData<fn() -> (M, T)>` (not `PhantomData<(M, T)>`) keeps `Column`
covariant and unconditionally `Send + Sync` regardless of `M` and `T`.

**Acceptance:** a `trybuild` UI-test suite asserting each mistake above fails to
compile *with the expected error message*.

## P3-03 · Enum generation

**Owner:** Vaibhav Gupta · **Est:** 3h

```rust
// src/db/enums.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, sqlx::Type, Serialize, Deserialize)]
#[sqlx(type_name = "role", rename_all = "SCREAMING_SNAKE_CASE")]
pub enum Role { User, Admin }

impl Role {
    pub const ALL: &'static [Role] = &[Role::User, Role::Admin];
    pub fn as_db_str(&self) -> &'static str { /* ... */ }
}
impl std::str::FromStr for Role { /* ... */ }
impl std::fmt::Display for Role { /* ... */ }
```

For SQLite the `#[sqlx(type_name)]` attribute is dropped and the enum derives
`Type` over `TEXT`. The **Rust-facing API is identical across dialects** — that is
the promise from ImplPlan03 being cashed in.

## P3-04 · Client root

**Owner:** Vaibhav Gupta · **Est:** 4h

```rust
// src/db/mod.rs
pub struct Db { pool: ruprizzle::Pool }

impl Db {
    pub async fn connect(url: &str) -> Result<Self, ruprizzle::Error>;
    pub fn from_pool(pool: ruprizzle::Pool) -> Self;

    /// Prisma-flavoured, per-model entry point.
    pub fn user(&self) -> UserRepo<'_>;
    pub fn post(&self) -> PostRepo<'_>;

    /// Drizzle-flavoured, free-form entry point.
    pub fn select<M: Model>(&self) -> SelectQuery<'_, M>;
    pub fn insert<M: Model>(&self) -> InsertQuery<'_, M>;

    pub async fn transaction<F, T>(&self, f: F) -> Result<T, Error>
    where F: for<'t> FnOnce(&'t mut Tx) -> BoxFuture<'t, Result<T, Error>>;

    /// Escape hatch — hands back the raw sqlx pool.
    pub fn raw_pool(&self) -> &sqlx::Pool<sqlx::Any>;
}
```

Both APIs over one engine. Prisma users reach for `db.user().find_many()`; SQL
people reach for `db.select::<User>()`. Neither is a second-class citizen, and
both lower to the same `SelectQuery`.

Also generate a prelude:

```rust
pub mod prelude {
    pub use super::{Db, user, post, User, Post, UserInsert, PostInsert};
    pub use ruprizzle::prelude::*;
}
```

## P3-05 · Emission mechanics

**Owner:** Vaibhav Gupta · **Est:** 4h

- Build a `proc_macro2::TokenStream` with `quote!`, then format with
  `prettyplease`. Never emit strings with `format!` — token-based emission cannot
  produce syntactically invalid Rust, and `prettyplease` gives stable formatting
  that keeps diffs of generated code reviewable.
- Idempotence is a hard requirement: running `generate` twice byte-for-byte
  matches. Enforced by a CI test.
- Reserved keywords: field `type` becomes `r#type`; `Column` const is `TYPE`.
- Write files atomically (temp + rename) so an interrupted generate never leaves a
  half-written module that breaks the user's build.
- If the output directory contains files not in the manifest, **do not delete
  them** — warn instead. Deleting user files is unforgivable; the CLI gets an
  explicit `--prune` flag for that.

### G3 sign-off evidence (2026-08-10)

All three blockers are closed and the gate now reads true: all four example
schemas, on both dialects, compile with zero warnings under `clippy::pedantic`.

1. **Column-token `trybuild` tests exist.** `crates/runtime/tests/trybuild/` now
   holds six cases. The four added — `col_eq_wrong_type`, `col_gt_on_string`,
   `col_contains_on_non_string`, `col_is_null_on_required` — cover the rest of
   the P3-02 table alongside the pre-existing cross-model case. `String` is
   deliberately `Encodable` but not `Ordered`, which is what makes `EMAIL.gt(..)`
   fail to compile.
2. **Snapshots cover the full matrix**: 4 examples × 2 dialects, 48 files. Two
   assertions carry real weight beyond the recorded output —
   `rust_api_is_identical_across_dialects` proves everything except `enums.rs` is
   byte-identical between Postgres and SQLite (cashing in ImplPlan03's promise),
   and `generation_is_idempotent` pins P3-05.
3. **The compile check covers the matrix and is pedantic-clean.** All eight
   variants are written as sibling modules of one crate, so it stays a single
   `cargo check`; this works because generated code only ever refers to its
   neighbours through `super::`, never absolute `crate::` paths.

**CI must run** `cargo test -p ruprizzle-codegen -- --ignored`. These two tests
stay `#[ignore]`d because they shell out to cargo (~24s), but they are the only
thing standing between a schema shape and broken generated code.

#### Three real codegen bugs this uncovered

Widening from blog-only immediately broke the build, which is the strongest
argument that the narrow gate was hiding rather than proving quality. All three
sat in `social`, the example with the self-relation:

- **Infinite type.** `Thread.parent` emitted `Related<Option<Thread>>` inline, so
  `Thread` had infinite size (E0072). Self-referential to-one relations are now
  boxed. `Vec` already provides indirection, so lists were unaffected and nothing
  else pays for it.
- **Duplicate binding.** The include-helper setter emitted
  `|parent, parent| parent.parent = parent` — the closure hardcoded `parent` as
  its row parameter, which collides whenever a relation field is itself named
  `parent` (E0415). Bindings are now `__row`/`__loaded`/`__child`.
- **Optional foreign keys emitted uncompilable code.** `Thread.parentId` is
  `Uuid?`; the generated getter returned `Option<Uuid>` where `Key = Uuid` was
  expected (E0308). The code even carried a comment saying optional keys were
  unsupported and that "callers will get a type error at compile time" — but
  shipping code that does not compile is a much worse failure than a missing
  helper. Codegen now skips the `include` helper for an optional FK; the relation
  field, its column token, and hand-written queries all still work.
